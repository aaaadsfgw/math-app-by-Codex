# Windows OCR Phase 3 の検証

## Windows での利用

`Setup Math Study Log.cmd` を一度実行してから、既存のデスクトップアイコンで起動する。
Ctrl+Shift+X で印刷体の問題を1問囲み、画像、問題番号、指示、変換後の数式を照合する。
必要に応じて入力欄を修正し、「問題文をコピー」を選ぶ。計算には Ctrl+Shift+Y または
設定した計算キーを使う。IBEM は設定から選択できる。

## 認識経路

- Windows 専用のレイアウト解析で行ごとのインクの広がりと横方向の間隔を測る。
  線の近くの上下に十分な文字幅と重なりがある場合に、分数を1つの領域として保つ。
  小さく近接する指数などは隣接する数式へまとめる。
- 上段や同一行の独立領域を Tesseract で読み、配置と文字列の両方を使って指示・番号を
  判定する。独立した小さな番号領域で Tesseract の括弧が曖昧な場合だけ Pix2Text の
  読みを追加する。同一行の番号と係数は候補を警告付きで示し、分割候補が競合した場合は
  元画像を見ながら入力できる状態にする。
- 公式 Pix2Text MFR 1.5 のリビジョン
  `1cef9f0bdcd6a4c63df7de1311fb0894593340cc` を使用する。初回取得と
  推論プロセス初期化時に SHA-256 とファイルサイズを照合する。公式 ONNX の前処理と
  逐次デコードは比較時と同じ実装を共有する。
  [モデルとライセンス](https://huggingface.co/breezedeus/pix2text-mfr-1.5/tree/1cef9f0bdcd6a4c63df7de1311fb0894593340cc)、
  [ハッシュ固定](../bench/ocr/models.lock.json)
- 既存の ONNX Runtime Web でも CPU 推論を構成できる。今回は比較時の ONNX Runtime
  CPU、画像処理、トークナイザーをそのまま再利用できる独立した Python プロセスを選んだ。
  メインプロセスは検証済みの PNG を標準入出力で渡し、モデルは最初の利用まで読み込まない。
  キャンセルと期限超過ではプロセスを終了し、次の認識で再起動する。
  [ONNX Runtime の Electron 向け資料](https://onnxruntime.ai/docs/tutorials/web/build-web-app.html)
- LaTeX は許可したコマンドだけを解析して構造を組み立て、既存の入力形式へ変換する。
  演算子や分数の上下は認識時の意味を保ち、不完全な表記では修正を求める。
  アプリは OCR を数学的検証として扱わず、コピーと計算は別々のユーザー操作とする。

## 固定画像での結果

Windows x64、Core i7-13620H、Electron 45.2.3、CPU 1スレッドで測定した。
数式34問は前回と同じ数式画像を推論とLaTeX変換に渡した。混合6問と未使用12問は
Electron の画像分割、OCR、変換、確認・コピーの入力検証を通した。12問は再現用の
MathMLから作成し、同一行の日本語・問題番号、係数、分数、指数、根号、定積分、片側極限を含む。

| 評価 | 数式の構造一致 | 問題番号一致 | 日本語一致 | 完全一致 |
| --- | ---: | ---: | ---: | ---: |
| 数式単体 | 31/34 | — | — | 31/34 |
| 既存混合画像 | 6/6 | 6/6 | 6/6 | 6/6 |
| 未使用画像 | 12/12 | 12/12 | 11/12 | 11/12 |

完全一致は数式の構造と付随する情報の一致を意味する。日本語の空白と句点は比較時に
取り除いた。前回の同じ画像では IBEM CPU が数式単体 7/34、IBEM を使う混合処理が
完全一致 0/6 だった。今回の未使用12問は前回の比較対象外。
解析できた数式で重大な演算子の誤認識は0件。解析不能な2件はこの数に含めない。
未使用4件に警告があり、そのうち3件は画像上の番号と係数を確認する案内で完全一致。

| 残った誤認識 | 処理 |
| --- | --- |
| 05 加減算の括弧が崩れた | LaTeX変換を拒否し、手動修正が必要 |
| 11 負号に不正な下付きが付いた | LaTeX変換を拒否し、手動修正が必要 |
| 13 立方根の指数が消えた | 平方根の候補が成立するため、元画像との照合が必要 |
| p3-12「簡単」が「簡里」になった | 指示を確定できず、修正するまでコピー不可 |

未使用の片側極限は、LaTeXの矢印装飾を本番変換器が明示的に解析できたため、変換後の
数式が一致した。旧比較用の生LaTeX採点器ではこの表記を扱わず、11/12だった。

| 工程 | 実測 |
| --- | ---: |
| Pix2Text 初回モデル初期化・ハッシュ確認 | 1.17秒 |
| 初回の数式推論 | 0.73秒 |
| 初回のプロセス起動から変換まで | 2.18秒 |
| ウォーム数式推論の中央値 | 約0.93秒 |
| 既存混合画像の認識の中央値 | 約1.9秒 |
| 未使用画像の認識の中央値 | 約1.2秒 |
| LaTeX変換の中央値 | 0.1ミリ秒未満 |

混合画像の時間には Electron OCR 画面の起動、レイアウト、日本語OCR、推論を含む。
メモリは子プロセスのみで Electron 全体を含まない。常駐時は未使用5分で
このプロセスを解放する。アイドル時の CPU 使用率は測定していない。

## Windows の画面取得と起動

セットアップを実行し、既存のデスクトップアイコンから約0.81秒でウィンドウが表示された。
Windows の表示倍率125%で、実際の Ctrl+Shift+X とマウスドラッグにより日本語と
数式が混じる問題を取り込み、候補の「(2)」「次の式を展開しなさい」「(x+2)*(x-3)」
を本番画面で確認した。ウィンドウを閉じて常駐した後、同じプロセスを
デスクトップアイコンから開き直せた。

独立した実画面テストでは、利用中の既定キーに代えて Ctrl+Shift+W で取り込み、
Ctrl+Shift+Q で計算した。算術、問題番号付き分数、日本語混在の3枚をキャプチャし、
3枚とも候補を確認してからコピーした。`2+3` の計算結果は検証済みの `5` になった。
システムのクリップボードにテキスト以外の形式があったため、このテストは
コピーと計算の両方に検証用クリップボードを使用した。

| 工程 | 初回・算術 | 2回目・番号付き分数 | 3回目・日本語混在 |
| --- | ---: | ---: | ---: |
| キーから選択表示 | 133 ms | 122 ms | 125 ms |
| 選択確定から画像取得 | 433 ms | 379 ms | 356 ms |
| モデル初期化 | 1,107 ms | 0 ms | 0 ms |
| 数式推論 | 456 ms | 634 ms | 538 ms |
| 番号の追加推論 | 0 ms | 416 ms | 0 ms |
| LaTeX変換・候補検証 | 3.47 ms | 0.84 ms | 1.02 ms |
| 選択表示から明示コピーまでの処理合計 | 2.63秒 | 1.85秒 | 1.38秒 |

合計にはドラッグと確認操作にかけた待ち時間を含まない。
