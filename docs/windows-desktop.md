# Math Study Log Windows 版

## 初回セットアップと普段の起動

1. Windows x64 と Node.js 22.12 以上を用意します。
2. プロジェクトフォルダーにある `Setup Math Study Log.cmd` をダブルクリックします。
   セットアップ画面に `Setup complete` が表示されれば完了です。依存関係や固定版
   Electron に加え、Pix2Text MFR 1.5 の重みと専用の Python CPU 環境を準備します。
   初回はネット接続が必要です。普段の起動と認識はオフラインで動作します。
3. デスクトップの **Math Study Log** をダブルクリックします。
   普段の起動では、ターミナルを開かずに現在のプロジェクト内の Electron を起動します。

GitHub から変更を取得したり Codex がソースを変更したりした後は、トレイで
「完全終了」を選び、デスクトップアイコンから起動し直します。通常のソース変更は
再インストールやビルドなしで反映されます。起動時の GitHub 更新確認はありません。
依存関係やモデルの固定版が変わった場合は、セットアップを再実行します。
専用環境と重みは `%LOCALAPPDATA%\Math Study Log\pix2text` に保存されます。

ショートカットにはプロジェクトの絶対パスが記録されます。移動・改名後に古い
ショートカットが開けなくなったら、移動先で `Setup Math Study Log.cmd` を
実行し直してください。同じデスクトップアイコンが新しい場所を指すようになります。

## 起動ログ

エクスプローラーのアドレス欄に `%LOCALAPPDATA%\Math Study Log\logs` と入力します。

- `launch.log` に起動元、Electron の終了コード、実行ファイルが見つからない場合などのエラーを記録します。
- `startup.log` にメインモジュール、画面、計算エンジンの初期化エラーを記録します。
- `electron.log` に Electron 内部の診断を記録します。
- `pix2text-setup.log` に専用環境のセットアップと固定モデルの取得時の診断を記録します。

移動などで Windows がショートカットの参照先のスクリプトを見つけられない場合は、
起動処理に到達しないため、新しいログは作られません。移動先でセットアップを実行してください。
端末の管理ポリシーで Windows Script Host が無効な場合は、開発用の
`npm.cmd run desktop` で起動できます。

## 操作

### 画面から数式を取り込む

1. 別のアプリに印刷体の数式を1問表示します。対応する短い日本語指示や問題番号があれば、数式と一緒に囲めます。
2. `Ctrl+Shift+X` を押し、同じモニター内で問題の周囲をドラッグします。`Esc` で中止できます。
3. Math Study Log が開き、元画像、問題番号、指示、変換後の数式、警告が表示されます。
   「認識したLaTeX」を開くと、Pix2Textの出力を確認できます。
4. 画像と照合し、必要なら「コピーする問題文」を編集して「問題文をコピー」を押します。
   「再認識」は現在の切り出し画像を使います。
5. `Ctrl+Shift+Y`（または設定済みの計算キー）でコピーした問題を計算します。

トレイ常駐中も両方のキーを利用できます。認識の中止はアプリ画面またはトレイメニューから行えます。
クリップボードは「問題文をコピー」を押し、入力チェックに通過した時点で更新されます。
構文のチェックに通った文字列でも、モデルが画像の符号や文字を読み違える場合があります。
問題番号は改行で数式と分けてコピーされます。確認画面の画像と候補は、閉じるか次の取得を始めるまでメモリに保持します。

画面取得には Electron のディスプレイ情報と `desktopCapturer` を使用します。
選択画面を撮影対象から除外し、ドラッグ終了時にすべての選択ウィンドウが閉じた後で撮影します。
モニターの実画像寸法を使って表示座標を画像ピクセルに変換します。
複数台のうち撮影対象を Electron の画面 ID で照合できない場合は、
Windows PowerShell を非表示で呼び出し、Windows の API で指定した矩形を取得します。
複数モニターでは各画面で個別に選択できます。モニターをまたぐドラッグや、Windows が画像を提供しない保護された画面には制限があります。

「ショートカットと常駐」の「数式OCRモデル」で切り替えられます。「自動」は専用環境が
あれば Pix2Text を使い、未セットアップの場合は IBEM を使います。IBEM は WebGPU を
優先し、利用できない場合は WASM を試します。Pix2Text のエラー時は、同じ画像で
IBEM を試す場合もモデル設定を切り替えてから再認識してください。

Pix2Text では、隔離した Electron 画面で画像から候補領域を切り出し、短い日本語を
同梱 Tesseract、数式をローカルの ONNX Runtime CPU プロセスに渡します。
モデルは最初の認識時に読み込み、認識間で再利用します。全体の上限は90秒、1回の
Pix2Text 呼び出しの上限は45秒です。5分間の未使用、認識の中止、またはアプリ終了で
推論プロセスを解放します。分割と精度の実測は [Phase 3 検証結果](windows-ocr-phase3.md) を参照してください。

### テキストを計算する

- Word やメモ帳などで問題をテキストとしてコピーし、`Ctrl+Shift+Y` を押します。
  検証済みの解答が得られたときにクリップボードが更新されます。
- 手入力では「計算する」を押し、表示された解答を「解答をコピー」でコピーします。
  手入力の計算自体はクリップボードを変更しません。
- 競合時は画面に登録失敗が表示されます。「ショートカットと常駐」で別の英字を選び、
  「登録」を押します。Chrome 側は `chrome://extensions/shortcuts` で割り当てを確認できます。
- 既定ではウィンドウを閉じても常駐します。通知領域のアイコンから画面を開き直すか、
  「完全終了」を選びます。アイコンは Windows の通知領域の折りたたみ内に入ることがあります。
  「ウィンドウを閉じても常駐する」を解除すると閉じる操作で終了します。
- 成否は Windows 通知に表示されます。開発起動では Windows の通知設定やスタートメニューの
  登録状況によりトーストが表示されない場合があります。最後の結果やエラーはアプリで確認できます。

## 共通エンジンと Windows 固有の処理

- 手入力は `solveWorkflow`、クリップボード計算は `runShortcutWorkflow` を通ります。
  入力検証、分類、計算、数学的検証、解答の書式は Chrome 版と共通です。
- Windows では各計算を Node ワーカーに隔離し、同梱 Algebrite への既存アダプターを
  `symbolicOperations` に接続します。ワーカーは起動時に動作確認し、計算ごとに生成・終了します。
  計算全体に 10 秒の上限とワーカーの JavaScript ヒープ上限を設けています。
- 入力は 4,096 文字以内のプレーンテキストです。空、曖昧、未対応、検証失敗、タイムアウト時は
  書き込みません。計算中の連打と完了直後の再入力を抑止し、書き込み直前にテキストの変更を確認します。
  Windows のクリップボードは他アプリと共有されるため、確認と書き込みの間に起きた変更や、
  テキストが同じまま書式だけが変わった場合は検知できません。
- メインプロセスがクリップボード、トレイ、設定を管理します。設定は Electron の
  ユーザーデータフォルダーに保存します。アプリは数式や解答の履歴を保存しません。

## 検証手順

```powershell
npm.cmd test
npm.cmd run check
```

自動テストは実際の計算ワーカーと、テスト用のクリップボード・キー登録を使用します。
Windows の実操作を確認する際は、以下を別に試します。

1. 起動し、準備完了とショートカットの登録状態が表示されることを確認します。
2. メモ帳を開き、下表の問題をコピーして、登録したショートカットを押します。
   別の場所へ貼り付けて期待値を確認します。同じ問題を手入力でも計算します。
3. 未対応の「円の面積を求めよ」や曖昧な `x2` をコピーして試し、元の文字列と
   エラー表示を確認します。空のクリップボードでも試します。
4. ショートカットを連打し、結果が一度だけコピーされることを確認します。
5. 常駐を有効にしてウィンドウを閉じ、メモ帳でショートカットを試します。
   トレイメニューからウィンドウを開き直します。
6. トレイメニューから完全終了し、同じキーが解放されることを確認します。
   常駐を無効にして、ウィンドウを閉じる操作でも終了することを確認します。

| 問題 | 期待する解答 |
| --- | --- |
| `(+19)+(-14)` | `5` |
| `2x^2-7x+3=0` | `x=1/2,3` |
| `f(x)=sin(3x^2) を微分せよ` | `6*x*cos(3*x^2)` |
| `∫ 2*x*cos(x^2) dx` | `sin(x^2)+C` |
| `lim_(x->1+) 1/(x-1)` | `+∞` |

### ローカルモデルを使った OCR の再現

```powershell
npm.cmd exec --no -- electron scripts/windows-ocr-smoke.mjs
npm.cmd exec --no -- electron scripts/windows-ocr-smoke.mjs --force-wasm
npm.cmd exec --no -- electron scripts/windows-screen-capture-smoke.mjs
npm.cmd exec --no -- electron scripts/windows-screen-capture-smoke.mjs --physical-capture
npm.cmd exec --no -- electron scripts/windows-phase3-ocr-smoke.mjs phase3-live.json
```

最初の2コマンドは Electron 内で描画した画像をローカル OCR に渡します。
画面取得の検証では Windows の実画面から表示中のテスト画像を切り出します。
`--physical-capture` は画面 ID を照合できない場合の Windows 経路を検証します。
グローバルキーと実クリップボードを含む操作は、前述の手順で確認できます。

以下は Phase 2 の IBEM を Windows の Electron 45.2.3 で WASM 実行したときの候補です。

| 入力画像 | 実際の候補 | 判定 |
| --- | --- | --- |
| `(1) (x²−5x+6)/(x−2)` | `(1)` と `((x ^2)/(s)) x + 6 lt.double 2` | 問題番号を分離。分子と分母に誤り |
| `3a(2a−b)−2b(a+3b)` | `3 ⟦a(2*a = b)⟧ - 2 ⟦b(a + 3*b)⟧` | 内側の減算が等号になり、乗算の構造が未確定 |
| `(1) 2ab(a+b)/(4a)` | `(1)` と `((2 a ⟦b(a + b)⟧)/(4*a))` | 問題番号と分母を保持。分子の乗算が未確定 |
| `次の式を計算しなさい` と `2+3` | `次の式を計算しなさい` と `2 + 3` | 指示と式を分離 |
